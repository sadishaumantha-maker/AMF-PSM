## 1. The dispute this project settles

Nine success metrics were declared, none is instrumented, and several are directly gameable - "PRs merged per week" rewards splitting one change into five. The dispute is whether to instrument the declared metrics as written or to replace them with measures that resist Goodhart's law.

## 2. Purpose

Instrument the metric set, and for each metric state its gaming mode and the counter-measure. A metric with no stated gaming mode is not shipped.

## 3. Scope

**In scope**

- A reproducible collection script for every metric, run from repository data only.
- A per-metric Goodhart analysis: how it is gamed, and what balancing measure prevents it.
- A dashboard page under `docs/` regenerated on demand, never by hand.

**Out of scope**

- Any metric requiring data the repository does not hold.
- Adding runtime dependencies to `amf`.

## 4. Instructions

Execute in order. Do not start a step until the previous step's artifact is committed.

1. For each of the nine metrics, write down the exact data source and the exact query.
2. Apply Goodhart's law and the Lucas critique: state precisely how each metric decouples from the goal once it is targeted.
3. Pair every gameable metric with a balancing measure (for example, PR count paired with median PR lifetime and revert rate).
4. Implement the collection as a script under `tools/` that writes a markdown table; no manual editing.
5. Publish `docs/governance/metrics.md` generated by that script.
6. Record the baseline values on the day of first run.

## 6. Autonomous agents

Each agent below runs unattended against this charter. An agent stops at its *stop condition* and hands its artifact to the next agent; no agent may widen its own mandate.

### `benchmark-runner`

- **Mandate:** Implement and run the metric collection script deterministically.
- **Inputs:** Repository history and CI artifacts.
- **Output artifact:** `tools/collect_metrics.py` plus generated table.
- **Stop condition:** Two consecutive runs on an unchanged repository produce byte-identical output.

### `red-team-critic`

- **Mandate:** Game every metric on paper and report the cheapest way to hit target without improving the repository.
- **Inputs:** The metric definitions.
- **Output artifact:** A gaming report with one attack per metric.
- **Stop condition:** Every metric has either a balancing measure or a written acceptance that it is advisory only.

### `docs-synthesizer`

- **Mandate:** Publish the metrics page and the Goodhart analysis.
- **Inputs:** Script output, gaming report.
- **Output artifact:** `docs/governance/metrics.md`.
- **Stop condition:** The page states, for each metric, its definition, its gaming mode and its counter-measure.

**Hand-off order:** `benchmark-runner` -> `red-team-critic` -> `docs-synthesizer`
