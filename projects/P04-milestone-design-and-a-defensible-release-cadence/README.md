## 1. The dispute this project settles

Gap 6 records "no sprint/release cycle - chaotic delivery cadence", while metric 9.3 asks for at least one merged pull request per week. The dispute is whether cadence should be time-boxed (fixed-length iterations) or scope-boxed (release when the milestone closes) for a repository whose work is predominantly research rather than feature delivery.

## 2. Purpose

Select a cadence model with evidence, define the milestone set that carries it, and write the quarterly release breakdown into `docs/roadmap.md`.

## 3. Scope

**In scope**

- A comparison of time-boxed versus scope-boxed cadence for research-heavy repositories.
- A milestone set covering Phases 1-5 of the roadmap.
- The v1.1 release scope decision and its CHANGELOG entry.

**Out of scope**

- Publishing anything to a public package index - forbidden by `RELEASING.md`.

## 4. Instructions

Execute in order. Do not start a step until the previous step's artifact is committed.

1. Extract delivery-throughput evidence from repository history: merge intervals, PR lifetimes, review latency.
2. Compare the two cadence models against that evidence and against the DORA capability findings.
3. Define milestones so that every milestone has an exit criterion that is a *fact*, not an estimate.
4. Assign every open issue to exactly one milestone.
5. Write the quarterly breakdown into `docs/roadmap.md`.
6. Decide and record the v1.1 scope; draft the CHANGELOG entry under `## [Unreleased]`.

## 6. Autonomous agents

Each agent below runs unattended against this charter. An agent stops at its *stop condition* and hands its artifact to the next agent; no agent may widen its own mandate.

### `benchmark-runner`

- **Mandate:** Produce reproducible delivery statistics from `git log` with the exact command recorded.
- **Inputs:** Repository history.
- **Output artifact:** `docs/governance/_data/delivery_stats.md` with commands.
- **Stop condition:** Every number can be regenerated by copying one command from the file.

### `spec-drafter`

- **Mandate:** Write the cadence decision record and the milestone exit criteria.
- **Inputs:** Delivery statistics, roadmap.
- **Output artifact:** `docs/governance/cadence.md`.
- **Stop condition:** Every milestone exit criterion is a checkable fact.

### `release-marshal`

- **Mandate:** Decide and document v1.1 scope; keep `pyproject.toml` and `__init__.py` versions in lockstep.
- **Inputs:** Milestone set, `CHANGELOG.md`.
- **Output artifact:** A drafted Unreleased CHANGELOG section.
- **Stop condition:** The two version strings agree and the entry follows Keep a Changelog.

**Hand-off order:** `benchmark-runner` -> `spec-drafter` -> `release-marshal`
