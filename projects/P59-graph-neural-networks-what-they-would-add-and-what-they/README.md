## 1. The dispute this project settles

Graph neural networks are proposed for the dependency structure. The framework is deterministic, interpretable, dependency-free and explicitly illustrative. A learned model would be none of those things, and there is no labelled training data of structural outcomes to learn from. Whether a GNN can be added without destroying what the framework is for has not been asked.

## 2. Purpose

Answer three questions in order - what would a GNN predict, what would it train on, and what would be lost - and only then consider whether any part of it belongs in this repository.

## 3. Scope

**In scope**

- A statement of the prediction target and the training data that would be required.
- An assessment of the determinism, interpretability and dependency costs.
- A recommendation, including the option of a separate research repository rather than this one.

**Out of scope**

- Adding any machine-learning dependency to the `amf` runtime package.
- Training on market data of any kind.
- Any claim of predictive performance.

## 4. Instructions

Execute in order. Do not start a step until the previous step's artifact is committed.

1. Name the prediction target precisely. 'Better structural analysis' is not a target; 'predict which system a shock will reach first' is.
2. Identify the training data that target requires, and confront the fact that the only available labels would be generated by the framework's own simulation - training a model to imitate the model.
3. State the costs explicitly: loss of determinism, loss of interpretability, and a heavyweight dependency in a package that currently has none.
4. Consult the interpretability literature on high-stakes decisions; the argument for interpretable-by-construction models is directly applicable to a diagnostic instrument.
5. If the recommendation is to explore anyway, recommend a separate repository so this package's guarantees are not weakened.
6. Publish the reasoning so the question does not have to be reopened from scratch.

## 6. Autonomous agents

Each agent below runs unattended against this charter. An agent stops at its *stop condition* and hands its artifact to the next agent; no agent may widen its own mandate.

### `literature-scout`

- **Mandate:** Collect the graph-learning primary sources and the interpretability argument for high-stakes settings.
- **Inputs:** The reading list.
- **Output artifact:** An annotated source table.
- **Stop condition:** Both the method sources and the interpretability counter-argument are represented.

### `spec-drafter`

- **Mandate:** Write the target, data and cost analysis and the recommendation.
- **Inputs:** The sources and the package's stated guarantees.
- **Output artifact:** `docs/methods/graph_learning.md`.
- **Stop condition:** The self-training circularity is addressed explicitly.

### `api-surface-reviewer`

- **Mandate:** State exactly which package guarantees a learned component would break.
- **Inputs:** `CLAUDE.md` guarantees and the proposal.
- **Output artifact:** A guarantee impact list.
- **Stop condition:** Determinism, zero-dependency and interpretability are each addressed.

### `red-team-critic`

- **Mandate:** Argue the strongest case for adoption and see whether the costs still dominate.
- **Inputs:** The draft.
- **Output artifact:** A dissent section.
- **Stop condition:** The dissent is answered on evidence, not on preference.

**Hand-off order:** `literature-scout` -> `spec-drafter` -> `api-surface-reviewer` -> `red-team-critic`
